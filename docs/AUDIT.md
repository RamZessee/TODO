# Проверка todo(1).zip

Дата: 21 октября 2026 года.

## Содержимое исходника

18 файлов: 10 PHP, один JavaScript, один CSS и 6 WebP. Проект без фреймворка и этапа сборки. PHP работает с MySQL через PDO, браузер обращается к JSON API через fetch.

Не было SQL-дампа, миграций, README, `.gitignore`, примера окружения, Docker, CI, тестов и лицензии. Код ожидал таблицу пользователей `todo`; `tasks` создавалась и дополнялась во время запросов API. Данные пользователей и задач отсутствовали.

В `data.php` были `localhost`, `todo_db`, пользователь `root` и пустой пароль. Других очевидных секретов, приватных ключей, токенов или паролей внешних сервисов при просмотре всех текстовых файлов не обнаружено. Проверка относится к этому архиву, а не к внешним аккаунтам или неизвестной истории Git.

## Исправления

| Проблема | Изменение |
| --- | --- |
| Нет воспроизводимой схемы БД | Начальная SQL-миграция пользователей и задач |
| Изменение схемы внутри API | Отдельный CLI-runner, журнал и контрольные суммы миграций |
| Открытый текст паролей | password_hash/password_verify и обновление хеша |
| MySQL root с пустым паролем | Окружение, отдельный пользователь, непустой пароль |
| Публичные и служебные файлы вместе | Разделение public/ и app/ |
| Нет CSRF-защиты | Токены POST-форм и API |
| ID сессии не обновлялся при входе | Обновление ID и токена, strict mode, HttpOnly, SameSite, настройка Secure |
| Редиректы после начала вывода HTML | Обработка страницы до вывода шаблона |
| Несуществующий маршрут form | Удалён, неизвестные страницы возвращают 404 |
| Готовый пароль в форме регистрации | Удалены предзаполненные данные, добавлена валидация |
| Некорректные JSON, методы и значения | Строгие проверки, лимиты текста и тела запроса |
| Успех при изменении отсутствующей задачи | 404 для отсутствующей или чужой задачи |
| Нет внешнего ключа владельца | FK, индекс владельца, уникальный email |
| Нет инструкций и проверок | README, Docker/Compose, скрипты, GitHub Actions и исключения |

Подготовленные SQL-запросы и проверка владельца задач уже были в исходнике и сохранены. Текст задач экранируется при выводе в браузере.

## Ограничения

Неизвестная старая база автоматически не обновляется. Миграции отказываются принимать существующие таблицы без записи начальной версии. Рабочие данные пользователей не создавались и не восстановлены в поставляемом проекте.

Не добавлялись восстановление пароля, подтверждение email и ограничение частоты входа. Публичный сайт дополнительно требует HTTPS, настройки сервера, защиты от перебора и резервных копий. Лицензия не выбиралась за автора.

## Проверки исполнения

Локальная среда: Windows, PHP 8.4.26, MariaDB 11.4.10, Node.js 24.13.0. Временные программы и тестовая база находятся вне поставляемого проекта.

- Все 14 PHP-файлов прошли проверку синтаксиса; JavaScript и Node HTTP-тест — `node --check`.
- Начальная миграция применилась на пустой базе; повторный запуск сообщил, что база актуальна.
- 52 HTTP-запроса прошли проверки регистрации, неверного пароля, повторного email, входа/выхода, обновления ID сессии и CSRF-токена, атрибутов cookie, личного кабинета, операций с задачами, отсутствующих и чужих задач, Unicode, ошибочного JSON, ограничений длины и недоступности внутренних файлов.
- HTTP-прогон выполнен с правами веб-пользователя только SELECT/INSERT/UPDATE/DELETE на таблицы пользователей и задач: изменение схемы при запросах не требуется.
- В базе проверены хеши паролей и запрет задач без существующего владельца внешним ключом.
- Скрипт миграций отказался изменять тестовую старую таблицу без журнала миграций; её структура и контрольная строка сохранены.
- `setup.php` создал случайные настройки и при повторном запуске отказался перезаписывать файл; его контрольная сумма не изменилась.
- `docker compose config --quiet` прошёл. Сборка Docker-образа и запуск именно MySQL 8.4 здесь не проверялись: Docker Engine недоступен. Подготовленный GitHub Actions ещё не запускался на GitHub.

При HTTP-прогоне обнаружено и исправлено поведение встроенного сервера PHP 8.4: запрос отсутствующего файла мог возвращать страницу входа с кодом 200. Теперь такие пути возвращают 404.

Тестовые учётные записи и пароли не включены в проект. Публикация в удалённый репозиторий не выполнялась.
