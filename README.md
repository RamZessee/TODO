# To-Do List

Учебное веб-приложение: регистрация, вход, личный кабинет и личная доска задач с тремя статусами, приоритетами, фильтрами и перетаскиванием карточек. Интерфейс на русском: канбан-доска с боковой навигацией, поиском, счётчиками колонок и прогрессом выполнения. Задачи открываются в боковой панели: описание, срок, до 5 цветных меток и чек-лист до 30 пунктов. На карточках видны дата и прогресс чек-листа, есть кнопка быстрого выполнения. Режим «Сегодня» собирает активные задачи на текущую дату и просроченные. Доступны фильтры по метке и просрочке, а поиск учитывает название, описание и метки. Боковая панель показывает три ближайшие задачи со сроком. На телефоне колонки прокручиваются горизонтально, детали открываются на весь экран. Светлая и тёмная темы переключаются кнопкой справа сверху; выбор сохраняется в браузере.

**Стек:** PHP 8.4, PDO MySQL, MySQL 8.4, HTML/CSS и обычный JavaScript. Composer, npm и сборка фронтенда для запуска не нужны. Node.js 22+ требуется только для автоматических HTTP-тестов.

Проект подготовлен из архива `todo(1).zip`. Схема базы восстановлена по запросам в коде; самих данных пользователей и задач в архиве не было. Подробнее — [отчёт проверки](docs/AUDIT.md).

## Запуск через Docker

Нужны работающий Docker Engine / Docker Desktop с Linux-контейнерами и Docker Compose v2 с поддержкой `--wait`. Выполняйте команды из папки с `compose.yaml`.

1. Скопируйте `.env.example` в `.env`:

   ```powershell
   # Windows PowerShell
   Copy-Item .env.example .env
   ```

   ```sh
   # Linux / macOS
   cp .env.example .env
   ```

2. В `.env` задайте два разных длинных случайных пароля: `DB_PASSWORD` и `MYSQL_ROOT_PASSWORD`. Не оставляйте их пустыми. Удобнее использовать буквы и цифры. Остальные настройки подходят для локального запуска.

   Если PHP уже установлен, вместо шагов 1–2 выполните `php scripts/setup.php`: он создаст `.env` со случайными паролями, не перезаписывая существующий файл.

3. Выполните:

   ```sh
   docker compose build
   docker compose up -d --wait db
   docker compose run --rm migrate
   docker compose up -d --wait app
   ```

4. Откройте [http://127.0.0.1:8080](http://127.0.0.1:8080). Нажмите **Go to registration**, создайте аккаунт и войдите. Готовых аккаунтов нет.

Порт сайта меняется через `APP_PORT`. Порт базы не публикуется на компьютере; Compose устанавливает для приложения `DB_HOST=db` и `DB_PORT=3306` независимо от этих строк в `.env`.

```sh
docker compose logs app db
docker compose down
```

Последняя команда останавливает контейнеры, сохраняя базу в Docker-томе. **Не добавляйте `-v`, если хотите сохранить данные**. После изменения исходников повторите сборку и запуск приложения; после добавления миграций запустите также сервис `migrate`.

Переменные MySQL создают базу и пользователя только при первом запуске с пустым томом. Изменение пароля в `.env` не меняет пароль уже существующего пользователя MySQL: изменять их нужно согласованно, сохранив резервную копию данных.

## Запуск без Docker

Нужны PHP 8.4 с расширениями `PDO`, `pdo_mysql`, `session`, `ctype` и MySQL 8.4. Расширения проверяются командой `php -m`. Для локальной проверки также использовалась MariaDB 11.4; это отдельная от Docker конфигурация.

1. Выполните `php scripts/setup.php` или скопируйте и заполните `.env.example` вручную.
2. Под администратором MySQL создайте **новую пустую** базу и отдельного пользователя. Замените `REPLACE_WITH_DB_PASSWORD` на пароль из своего `.env`; SQL с настоящим паролем в Git не сохраняйте:

   ```sql
   CREATE DATABASE todo_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   CREATE USER 'todo_app'@'localhost' IDENTIFIED BY 'REPLACE_WITH_DB_PASSWORD';
   GRANT ALL PRIVILEGES ON todo_db.* TO 'todo_app'@'localhost';
   ```

   Эти права ограничены одной базой и подходят для локальной разработки и миграций. Для удалённой базы настройте соответствующий адрес пользователя на её сервере.

3. В `.env` укажите адрес и порт базы, её имя, пользователя и пароль. `MYSQL_ROOT_PASSWORD` нужен только Docker, PHP его не использует.
4. Запустите:

   ```sh
   php scripts/migrate.php
   php -S 127.0.0.1:8080 -t public
   ```

5. Откройте [http://127.0.0.1:8080](http://127.0.0.1:8080).

Встроенный PHP-сервер предназначен для локальной разработки. На хостинге используйте Apache/Nginx с PHP и корневую папку сайта **`public/`**. Не публикуйте корень проекта целиком.

## Настройки

| Переменная | Назначение |
| --- | --- |
| `DB_HOST`, `DB_PORT` | Адрес и порт MySQL; в Docker задаются автоматически |
| `DB_NAME` | Имя базы, по умолчанию `todo_db` |
| `DB_USER` | Пользователь базы, по умолчанию `todo_app` |
| `DB_PASSWORD` | Непустой пароль пользователя базы |
| `MYSQL_ROOT_PASSWORD` | Пароль администратора базы Docker |
| `APP_PORT` | Локальный порт Docker, по умолчанию `8080` |
| `SESSION_SECURE` | `false` для локального HTTP, `true` для сайта за HTTPS |
| `APP_ENV` | Метка окружения; сама по себе не включает отладку или защиту |

Переменные процесса имеют приоритет над `.env`. PHP читает буквальные `KEY=value`, без подстановок переменных и escape-последовательностей. Комментарии пишите на отдельных строках. Для одинакового поведения PHP и Compose заключайте значения со специальными символами в одинарные кавычки. Пароли из `setup.php` этого не требуют.

`.env` исключён из Git и Docker-образа. В репозитории хранится только пустой пример.

## База и миграции

`database/migrations/001_initial.sql` создаёт:

- `todo`: пользователи, уникальный email, хеш пароля, дата создания. Исходное имя таблицы сохранено.
- `tasks`: название, статус, приоритет, владелец и дата создания; внешний ключ на пользователя и индекс для выборки его задач. Миграция `002_task_details.sql` добавляет описание, срок, метки и чек-лист, сохраняя существующие записи. Срок задаётся календарной датой без времени; незавершённая задача становится просроченной на следующий день по местному времени браузера. Изменения в панели сохраняются кнопкой.

Скрипт миграций отдельно создаёт `schema_migrations` с версиями и контрольными суммами. Повторный запуск пропускает уже применённые файлы. Применённый SQL не редактируйте: добавляйте новый файл с новым номером.

**Запускайте SQL через `scripts/migrate.php`, а не ручным импортом перед ним.** Без записи в журнале миграций скрипт намеренно отказывается менять существующие `todo`/`tasks`. Прерванную миграцию нужно проверить вручную: MySQL не откатывает все изменения схемы транзакцией.

Старая база не приложена, поэтому автоматическое обновление неизвестной схемы не выполняется. Если она у вас сохранилась, сначала создайте резервную копию. Старые пароли хранились открытым текстом, а новая версия принимает только хеши `password_hash`: потребуется безопасный сброс паролей или повторная регистрация и отдельный перенос задач с сопоставлением владельцев. Дамп с пользователями не публикуйте.

## Проверки

```sh
php scripts/lint.php
node --check public/ToDoListJs.js
node --check scripts/smoke.mjs
```

Без локального PHP:

```sh
docker compose run --rm --no-deps app php scripts/lint.php
```

Для работающего приложения с **отдельной тестовой базой**:

```sh
node scripts/smoke.mjs http://127.0.0.1:8080 --allow-test-writes
```

HTTP-тест проверяет регистрацию, вход/выход, смену сессии, CSRF, операции с задачами, изоляцию пользователей, Unicode, ошибочные данные и недоступность служебных файлов. Он создаёт два тестовых аккаунта; задачи удаляет, аккаунты оставляет. Не запускайте его на рабочей базе с важными данными.

В `.github/workflows/ci.yml` подготовлен GitHub Actions: сборка, синтаксис, двукратный запуск миграций и HTTP-тесты на временной базе. Workflow начнёт выполняться после загрузки репозитория, если GitHub Actions разрешены. Пароли в workflow предназначены только для одноразовой базы CI.

## Публикация в GitHub

Создайте пустой репозиторий в своём аккаунте. В папке этого проекта выполните:

```sh
git init -b main
git add .
git status
git diff --cached --stat
```

Проверьте, что среди файлов нет `.env`, дампов, логов и личных данных, затем:

```sh
git commit -m "Prepare To-Do application for GitHub"
git remote add origin https://github.com/YOUR_ACCOUNT/YOUR_REPOSITORY.git
git push -u origin main
```

Замените URL на адрес своего репозитория. Потребуется авторизация GitHub; не помещайте токен в URL или файлы. Эти команды приведены для самостоятельной публикации. При подготовке удалённый репозиторий не создавался и код не отправлялся.

**GitHub Pages не запускает PHP/MySQL:** это [хостинг статических сайтов](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages). Для работающего сайта нужен PHP/MySQL-хостинг или сервер с Docker. Локальный Compose привязывает сайт к `127.0.0.1`; публичный запуск требует настройки домена, HTTPS и веб-сервера/reverse proxy.

## Перед публичным запуском

Настройте HTTPS, `SESSION_SECURE=true`, резервные копии и отдельные секреты. Для веб-приложения достаточно `SELECT`, `INSERT`, `UPDATE`, `DELETE` на `todo` и `tasks`; миграции выполняйте другой учётной записью с правами изменения схемы этой базы.

В учебном проекте нет восстановления пароля, подтверждения email и ограничения частоты входа. Для публичного сервиса потребуется добавить эти функции и защиту от перебора. Подготовка к репозиторию не означает завершённую эксплуатационную настройку сервера.
